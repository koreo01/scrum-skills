# PBI Template Bug

check-bug.md のチェックを通過しやすい Bug チケットの雛形を出力します。

## コマンド形式

```
/pbi:template-bug [--title "タイトル"]
```

| 引数 | 説明 |
|-----|------|
| `--title "タイトル"` | タイトルをあらかじめ埋めた状態で出力 |
| （省略） | 全フィールドが空欄の雛形を出力 |

---

## 使い方

> **議事録由来で作成する場合**: 先に `/pbi:invoke-story-ticket-helper` を実行してチケット候補を抽出してください。

1. このコマンドを実行すると、下記テンプレートを出力します
2. `[...]` で囲まれた部分を実際の内容に置き換えてください
3. 記載後に `/pbi:check-bug` で品質確認してください

---

## 出力テンプレート

以下のテンプレートをそのまま出力する：

```markdown
# [Bugタイトル]
<!-- Title形式: 不具合を表す形式 -->
<!-- 例: 「〇〇が動かない」「△△でエラーが発生」「🔳🔳が表示されない」「××すると落ちる」 -->
<!-- NG例: 「〇〇したい」（Needs形式） / 「〇〇を改善する」（Tech形式） -->
[機能/画面]が[不具合の内容]

## 事実
<!-- 必須: 発生を確認した事実を記載 -->
<!-- 例: 「YYYY/MM/DD HH:mm、私は〇〇ボタンをクリックしても画面が遷移しないのを見た。」 -->
[YYYY/MM/DD HH:mm]、[誰が/どこで] [何をしたら] [何が起きた] のを見た/記録されている。

## 再現手順
<!-- 必須: 番号付きで3ステップ以上 -->
1. [操作1]
2. [操作2]
3. [操作3: この操作でバグが発生]

## 環境
<!-- 必須: OS + ブラウザ + バージョンが揃うと ✅ -->
- OS: [macOS 14.0 / Windows 11 等]
- ブラウザ: [Chrome 122.0 / Safari 17.0 等]
- ユーザー種別: [管理者 / 一般ユーザー 等]

## 期待動作
<!-- 必須: 本来どうなるべきか -->
[正しく動作した場合の挙動]

## 実際動作
<!-- 必須: 実際に何が起きているか -->
[バグが起きたときの実際の挙動]

## 再現率
<!-- 推奨: 常に / 時々 / 特定条件で のいずれか -->
- [ ] 常に再現
- [ ] 時々再現（頻度: ）
- [ ] 特定条件で再現（条件: ）

## エビデンス
<!-- 推奨: 省略すると check-bug.md で ❌ -->
- [ ] スクリーンショット（添付: ）
- [ ] エラーログ（添付: ）
- [ ] 動画

## 影響範囲
<!-- 推奨: どのユーザー・機能・環境に影響するか -->
[影響を受けるユーザー / 機能 / 範囲]

## 解釈（任意）
[この事実] から、[こういう原因だ] と私は推測している。
```

## GitHub ラベル設定ガイド

| プロパティ | 値 | 設定タイミング |
|-----------|-----|-------------|
| Type | Bug | 作成時 |
| Status | Triage | 起票時（調査・判断待ち） |
| Owner | Business | 起票〜Refiningまで（必須） |

### Owner × Status の整合ルール

| Status | Owner |
|--------|-------|
| Triage / Refining | Business |
| Story Defined 以降 | Product |

---

## check-bug.md チェック項目との対応

| チェック項目 | テンプレートの対応箇所 |
|------------|----------------------|
| 0-1 Status有効値 | プロパティ設定ガイド参照 |
| 0-2 Owner設定 | プロパティ設定ガイド参照 |
| 0-3 Owner×Status整合 | Owner × Status の整合ルール参照 |
| 1 事実セクション存在 | `## 事実` セクション |
| 2 再現手順の存在 | `## 再現手順` セクション |
| 3 環境情報の存在 | `## 環境` セクション |
| 4 Title形式（不具合形式） | 1行目のタイトル |
| 5 再現手順が番号付き | 1. 2. 3. の番号付きリスト |
| 6 期待動作の記載 | `## 期待動作` セクション |
| 7 実際動作の記載 | `## 実際動作` セクション |
| 8 時間情報の具体性 | 事実の冒頭「YYYY/MM/DD HH:mm」 |
| 9 再現率の記載 | `## 再現率` セクション |
| 10 エビデンスの有無 | `## エビデンス` セクション |
| 11 影響範囲の記載 | `## 影響範囲` セクション |

## よくある記載ミス

| ミスのパターン | 正しい書き方 |
|-------------|------------|
| 事実: 「今朝発生した」 | 「2026/04/01 09:30頃、私は〜を見た」（具体的な日時） |
| 再現手順が「〜すると発生」1行のみ | 3ステップ以上の番号付きで記載（チェックで⚠️） |
| 環境: 「Chromeで発生」 | OS・ブラウザ・バージョンをすべて記載 |
| 期待動作と実際動作が同じ記述 | 「本来どうなるべきか」と「実際に何が起きたか」を分けて記載 |
| エビデンスなし | スクリーンショットまたはエラーログを添付（チェックで❌） |
