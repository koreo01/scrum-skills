# PBI Template Tech

check-tech.md のチェックを通過しやすい Tech Issue チケットの雛形を出力します。

## コマンド形式

```
/pbi:template-tech [--title "タイトル"]
```

| 引数 | 説明 |
|-----|------|
| `--title "タイトル"` | タイトルをあらかじめ埋めた状態で出力 |
| （省略） | 全フィールドが空欄の雛形を出力 |

---

## 使い方

> **議事録由来で作成する場合**: 先に `/pbi:invoke-story-ticket-helper` を実行してチケット候補を抽出してください。

1. このコマンドを実行すると、下記テンプレートを出力します
2. `[...]` で囲まれた部分を実際の内容に置き換えてください
3. 記載後に `/pbi:check-tech` で品質確認してください

---

## 出力テンプレート

以下のテンプレートをそのまま出力する：

```markdown
# [Tech Issueタイトル]
<!-- Title形式: 現在の困った「状態」を表す形式 -->
<!-- 効率系: 「〜がやりづらい」「〜に時間がかかる」「〜が遅い」 -->
<!-- 属人系: 「〜しか作業できない」「〜が属人化している」 -->
<!-- 欠如系: 「〜が存在しない」「〜がない」「〜が未整備」 -->
<!-- 品質系: 「〜が複雑すぎる」「〜のカバレッジが低い」「〜が理解しにくい」 -->
<!-- 制約系: 「〜に対応できない」「〜が制限される」「〜でしか動かない」 -->
<!-- NG例: 「〜を実装する」「〜を改善する」（Task形式） / 「〜したい」（Needs形式） -->
[対象]が[課題の状態]

## 事実
<!-- 必須: 以下の4種類から1つ以上を選んで記載。定量データ（時間・回数・頻度）を含めると ✅ -->

<!-- ▼ 記録: [いつ]、[システム/ツール名] に [こう記録されている]。 -->
<!-- ▼ 発言: [いつ・どこで]、[誰] が [こう言った/書いた]。 -->
<!-- ▼ 伝聞: [誰] から、[別の誰] が [こう言っていた] と聞いた。 -->
<!-- ▼ 観察: [いつ・どこで]、私は [こうなっているの] を見た/聞いた。 -->
[YYYY/MM/DD]、[事実の記載（上記4種類のいずれかの形式で）]

## 解釈
<!-- 必須: 事実を参照し、読み取った意味と別の結びつけ方の両方を記載 -->
[上記の事実] から、[こういう意味だ] と私は読んでいる。
なぜなら [この事実] と [別の知識・事実・経験] を結びつけているからだ。
（ただし [別の結びつけ方] もありうる。）
```

## GitHub ラベル設定ガイド

| プロパティ | 値 | 設定タイミング |
|-----------|-----|-------------|
| Type | Tech | 作成時 |
| Status | Triage | 起票時（調査・判断待ち） |
| Owner | Business | 起票〜Refiningまで（必須） |

### Owner × Status の整合ルール

| Status | Owner |
|--------|-------|
| Triage / Refining | Business |
| Story Defined 以降 | Product |

## check-tech.md チェック項目との対応

| チェック項目 | テンプレートの対応箇所 |
|------------|----------------------|
| 0-1 Status有効値 | プロパティ設定ガイド参照 |
| 0-2 Owner設定 | プロパティ設定ガイド参照 |
| 0-3 Owner×Status整合 | Owner × Status の整合ルール参照 |
| 1 事実セクション存在 | `## 事実` セクション |
| 2 解釈セクション存在 | `## 解釈` セクション |
| 3 セクション分離 | 事実と解釈を別セクションに分離 |
| 4 Title形式（状態形式） | 1行目のタイトルとコメント |
| 5 プレースホルダー残存なし | `[...]` 形式で明示 |
| 6 事実の種類明示 | 4種類のコメントを参照 |
| 7 時間情報の具体性 | 事実の冒頭「YYYY/MM/DD」 |
| 8 影響範囲の記載 | 事実セクションで誰が困っているか記載 |
| 9 事実→解釈の参照 | 解釈の冒頭「[上記の事実] から」 |
| 10 別解釈の言及 | 解釈末尾「（ただし〜もありうる。）」 |
| 11 定量データの有無 | 事実のコメント「定量データを含めると ✅」 |

## よくある記載ミス

| ミスのパターン | 正しい書き方 |
|-------------|------------|
| Title: 「〇〇インターフェースを設計・実装する」 | 「〇〇インターフェースが存在しない」（欠如系の状態表現） |
| Title: 「〇〇したい」 | Tech ではなく Needs の可能性。Needs テンプレートを使う |
| 事実: 「最近、〇〇が遅い」 | 「2026/03/20以降、〇〇に〇〇分と記録されている」（具体的な日付と数値） |
| 解釈に「ただし〜もありうる」がない | 別の解釈の可能性を必ず記載（チェックで⚠️） |
| 解釈が事実を参照していない | 「[上記の事実] から」のように事実を明示して参照する |
| 定量データなし | 時間・回数・頻度など数値を含める（「28分」「週3回」等） |
