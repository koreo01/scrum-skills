# PBI Template Request

check-request.md のチェックを通過しやすい Request チケットの雛形を出力します。

## コマンド形式

```
/pbi:template-request [--title "タイトル"]
```

| 引数 | 説明 |
|-----|------|
| `--title "タイトル"` | タイトルをあらかじめ埋めた状態で出力 |
| （省略） | 全フィールドが空欄の雛形を出力 |

---

## 使い方

> **議事録由来で作成する場合**: 先に `/pbi:invoke-story-ticket-helper` を実行してチケット候補を抽出してください。

1. このコマンドを実行すると、下記テンプレートを出力します
2. `[...]` で囲まれた部分を実際の内容に置き換えてください
3. 記載後に `/pbi:check-request` で品質確認してください

---

## 出力テンプレート

以下のテンプレートをそのまま出力する：

```markdown
# [Requestタイトル]
<!-- Title形式: 依頼形式 -->
<!-- 例: 「〇〇株式会社様の環境構築依頼」「△△社様のSSO設定変更依頼」「🔳🔳社様のデータ移行依頼」 -->
<!-- NG例: 「〇〇したい」（Needs形式） / 「〇〇がやりづらい」（Tech形式） / 「〇〇が動かない」（Bug形式） -->
[会社名]様の[依頼内容の種別]依頼

【依頼者情報】
- 会社名: [会社名]
- 担当者: [担当者名]
- 連絡先: [メールアドレス / 電話番号]

【受領確認】
- 依頼受領日: [YYYY/MM/DD]
- 受領経緯: [メール / 電話 / ミーティング]

【依頼内容】
[何を依頼されているか。具体的に記載する]

【期限】
- 希望納期: [YYYY/MM/DD]
- 必須期限: [YYYY/MM/DD]（理由: [契約開始日など]）

【必要情報】
- [作業に必要な情報1]
- [作業に必要な情報2]
- [作業に必要な情報3]

【成果物/完了条件】
[何をもって完了とするか。顧客が確認・承認する基準を記載]

【備考】
[その他特記事項]
```

### 環境構築依頼の場合（該当時のみ追記）

```markdown
【環境情報】
- 環境種別: □ 本番 / □ ステージング / □ 検証
- テナント名: [テナント名]
- 初期ユーザー数: [人数]
- 管理者情報:
  - 名前: [管理者名]
  - メール: [メールアドレス]

【オプション設定】
- SSO: □ 有効 / □ 無効
- IP制限: □ 有効 / □ 無効
- その他: [特記事項]
```

## GitHub ラベル設定ガイド

| プロパティ | 値 | 設定タイミング |
|-----------|-----|-------------|
| Type | Request | 作成時 |
| Status | Triage | 起票時（受領・精査待ち） |
| Owner | Business | 起票〜Refiningまで（必須） |

### Owner × Status の整合ルール

| Status | Owner |
|--------|-------|
| Triage / Refining | Business |
| Story Defined 以降 | Product |

### Task直行ルート（重要）

RequestはRequirementを経由しない。依頼内容が整ったら**直接Taskを起票する**。

```
Request → Triage → Refining → Story Defined（Task起票）→ In Sprint → Done
```

## check-request.md チェック項目との対応

| チェック項目 | テンプレートの対応箇所 |
|------------|----------------------|
| 0-1 Status有効値 | プロパティ設定ガイド参照 |
| 0-2 Owner設定 | プロパティ設定ガイド参照 |
| 0-3 Owner×Status整合 | Owner × Status の整合ルール参照 |
| 0-4 Task直行ルートの確認 | Task直行ルート参照（Requirementは紐づけない） |
| 1 依頼者情報の存在 | `【依頼者情報】` セクション |
| 2 依頼内容の存在 | `【依頼内容】` セクション |
| 3 期限情報の存在 | `【期限】` セクション |
| 4 Title形式（依頼形式） | 1行目のタイトルとコメント |
| 5 会社名の明記 | `【依頼者情報】` の会社名フィールド |
| 6 期限の具体性 | 期限の「YYYY/MM/DD」形式 |
| 7 成果物/完了条件 | `【成果物/完了条件】` セクション |
| 8 必要情報の網羅性 | `【必要情報】` セクション |
| 9 連絡先の記載 | `【依頼者情報】` の連絡先フィールド |
| 10 環境情報（該当時） | `【環境情報】` セクション（環境構築の場合） |
| 11 受領確認 | `【受領確認】` セクション |

## よくある記載ミス

| ミスのパターン | 正しい書き方 |
|-------------|------------|
| Title: 「〇〇機能の改善を依頼された」 | 「〇〇株式会社様の〇〇機能改善依頼」（会社名+依頼形式） |
| Title: 「〇〇したい」 | Request ではなく Needs の可能性。Needs テンプレートを使う |
| 期限: 「なるべく早く」「急ぎ」 | 「希望納期: 2026/04/15」（具体的な日付で記載） |
| 成果物/完了条件が未記載 | 「何をもって完了とするか」を顧客と合意した基準で記載 |
| 受領確認が未記載 | 「依頼受領日: YYYY/MM/DD」と「受領経緯: メール/電話/ミーティング」を追記 |
| 環境構築なのに環境情報なし | 「【環境情報】」セクションを追記し、環境種別・テナント名・管理者情報を記載 |
| Requirementを紐づけている | RequestはTask直行ルート。Requirementは不要（チェックで❌） |
