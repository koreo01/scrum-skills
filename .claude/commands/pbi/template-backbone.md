# PBI Template Backbone

check-backbone.md のチェックを通過しやすい Backbone チケットの雛形を出力します。

## コマンド形式

```
/pbi:template-backbone [--title "タイトル"]
```

| 引数 | 説明 |
|-----|------|
| `--title "タイトル"` | タイトルをあらかじめ埋めた状態で出力 |
| （省略） | 全フィールドが空欄の雛形を出力 |

---

## 使い方

1. このコマンドを実行すると、下記テンプレートを出力します
2. `[...]` で囲まれた部分を実際の内容に置き換えてください
3. 記載後に `/pbi:check-backbone` で品質確認してください

---

## 出力テンプレート

以下のテンプレートをそのまま出力する：

```markdown
# [Backboneタイトル]
<!-- Title形式: テーマ/目標形式 -->
<!-- 例: 「ユーザーオンボーディング体験の改善」「検索機能の精度強化」「マルチテナント対応の実現」 -->
<!-- NG例: 「〜するフロー」（Narrative Flow形式）/ 「〇〇は△△できる」（Story形式）/ 「〜を実装する」（Task形式） -->
[対象領域]の[テーマ/目標]

【概要】
[このBackboneが実現したい大目標・価値の要約]
<!-- ユーザー・顧客・ビジネスへの価値を中心に記述する。実装詳細（API・DB・マイクロサービス等）は書かない -->

【対象ユーザー/顧客セグメント】
[このBackboneの恩恵を受けるユーザー・顧客セグメントの属性]
<!-- 例: 「新規登録ユーザー（契約後7日以内）」「管理者ロールを持つユーザー」「エンタープライズプランの顧客」 -->

【ゴール/理想状態】
[このBackboneが達成されたときに実現している状態・指標]
<!-- 定量指標が望ましい。例: 「〇〇率が△△%以上」「〇〇件数が△△%削減」「〇〇がXXできる状態」 -->
- [指標1]: [目標値]
- [指標2]: [目標値]

【スコープ】
- 対象: [このBackboneが取り扱うこと]
- 対象外: [このBackboneで扱わないこと]

【配下Narrative Flow】（Status=Story Defined以降は必須）
- [ ] #xxxx: [Narrative Flow1のタイトル（「〇〇が△△するフロー」形式）]
- [ ] #xxxx: [Narrative Flow2のタイトル]
```

## GitHub ラベル設定ガイド

| プロパティ | 値 | 設定タイミング |
|-----------|-----|-------------|
| Type | Backbone | 作成時 |
| Status | Refining | 起票時（テーマ・目標を精査中） |
| Owner | Business | 起票〜Refiningまで（必須） |

### Owner × Status の整合ルール

| Status | Owner |
|--------|-------|
| Refining | Business |
| Story Defined 以降 | Product |

### Backboneに存在しないプロパティ

- **Triage ステータスなし**: Backbone の Status は `Refining / Story Defined / Done` の3段階のみ
- **親チケットなし**: Backbone はチケット階層の最上位。本文に `Parent: #xxx` を記載しない
- **Workflow State なし**: Backbone には Workflow State プロパティが存在しない

## check-backbone.md チェック項目との対応

| チェック項目 | テンプレートの対応箇所 |
|------------|----------------------|
| 0-1 Status有効値 | プロパティ設定ガイド参照（Refining / Story Defined / Done） |
| 0-2 Owner設定 | プロパティ設定ガイド参照 |
| 0-3 Owner×Status整合 | Owner × Status の整合ルール参照 |
| 1 Title形式（テーマ/目標形式） | 1行目のタイトルとコメント |
| 2 概要/目的の存在 | `【概要】` セクション |
| 3 対象ユーザー/顧客セグメント | `【対象ユーザー/顧客セグメント】` セクション |
| 4 配下Narrative Flow/Storyリンク | `【配下Narrative Flow】` セクション（Story Defined以降は必須） |
| 5 ゴール/理想状態の記述 | `【ゴール/理想状態】` セクション |
| 6 スコープの示唆 | `【スコープ】` セクション |
| 7 ビジネス/ユーザー価値視点 | `【概要】` のコメント（実装詳細なし） |
| 8 Narrative Flow分解可能性 | `【配下Narrative Flow】` の箇条書き構造 |
| 9 タイトル・概要・ゴールの一貫性 | タイトル・概要・ゴールを同じテーマで統一 |

## よくある記載ミス

| ミスのパターン | 正しい書き方 |
|-------------|------------|
| Title: 「ユーザーが初回ログインするフロー」 | 「〜するフロー」は Narrative Flow の形式。「ユーザーオンボーディング体験の改善」のようなテーマ形式で記載 |
| Title: 「〇〇機能は△△できる」 | Story の形式。Backbone は機能仕様ではなくテーマ・目標を記述する |
| Title: 「〇〇を実装する」 | Task の形式。Backbone は作業指示ではなくビジネス/ユーザー価値の目標を記述する |
| 概要に「APIを〇〇する」「DBスキーマを変更する」 | 実装詳細はBackboneに書かない。ユーザー価値・ビジネス目標で記述する |
| ゴール: 「使いやすくする」「改善する」 | 定量指標または定性的な達成状態を具体的に記述（例: 「初回ログイン完了率90%以上」） |
| Status=Story Defined なのに配下Narrative Flowリンクなし | Story Defined 以降は配下Narrative Flow（#xxxx）へのリンクが必須 |
| 親チケットを設定している | Backbone は最上位チケット。本文に `Parent: #xxx` を記載しない（チェックで❌） |
