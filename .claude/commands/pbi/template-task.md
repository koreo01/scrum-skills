# PBI Template Task

check-task.md のチェックを通過しやすい Task チケットの雛形を出力します。

## コマンド形式

```
/pbi:template-task [--title "タイトル"]
```

| 引数 | 説明 |
|-----|------|
| `--title "タイトル"` | タイトルをあらかじめ埋めた状態で出力 |
| （省略） | 全フィールドが空欄の雛形を出力 |

---

## 使い方

> **議事録由来で作成する場合**: 先に `/pbi:invoke-story-ticket-helper` を実行してチケット候補を抽出してください。

1. このコマンドを実行すると、下記テンプレートを出力します
2. `[...]` で囲まれた部分を実際の内容に置き換えてください
3. 記載後に `/pbi:check-task` で品質確認してください

---

## 出力テンプレート

以下のテンプレートをそのまま出力する：

```markdown
# [Taskタイトル]
<!-- Title形式: 作業形式 -->
<!-- 例: 「〇〇を〇〇する」「〇〇の△△対応」「〇〇の△△を追加/修正する」 -->
<!-- NG例: 「〇〇は△△できる」（Story形式） / 「〇〇が動かない」（Bug形式） -->
[対象]を[作業内容]する

## 背景/目的
<!-- 必須: なぜこのTaskが必要かを記載 -->
<!-- 元RequestまたはIssueの#xxxを必ず参照する -->
【元Request/Issue】[#xxx]
[なぜこのTaskが必要か・どんな問題を解決するか]

## 作業内容
<!-- 具体的に何をするか -->
- [作業1]
- [作業2]
- [作業3]

## 完了条件
<!-- 必須: 客観的に判定可能な条件を列挙 -->
<!-- NG: 「正しく動作すること」「適切に設定すること」（曖昧表現） -->
<!-- OK: 「〜が設定されていること」「〜テストがパスしていること」「〜を確認済みであること」 -->
- [ ] [完了条件1: 観察・確認できる状態を記載]
- [ ] [完了条件2]
- [ ] [完了条件3]

## SubTask候補（任意）
- [ ] [SubTask1]
- [ ] [SubTask2]
```

## GitHub ラベル設定ガイド

| プロパティ | 値 | 設定タイミング |
|-----------|-----|-------------|
| Type | Task | 作成時 |
| Status | Story Defined | 作成時 |
| Workflow State | Backlog | 作成時 |
| Planned Release Version | [バージョン] | スプリント投入時（必須） |
| Released Version | [バージョン] | Done後・リリース完了時（必須） |

## check-task.md チェック項目との対応

| チェック項目 | テンプレートの対応箇所 |
|------------|----------------------|
| 0-1 Status有効値 | プロパティ設定ガイド参照 |
| 0-2 Workflow State有効値 | プロパティ設定ガイド参照 |
| 0-3 Planned Release Version | プロパティ設定ガイド参照 |
| 1 Title形式（作業形式） | 1行目のタイトル |
| 2 背景/目的の存在 | `## 背景/目的` セクション |
| 3 完了条件の存在 | `## 完了条件` セクション |
| 4 完了条件の具体性 | 完了条件のコメント参照 |
| 5 完了条件の網羅性 | 完了条件を3件以上記載 |
| 6 曖昧表現なし | 完了条件のNG例参照 |
| 7 元チケットリンク | 背景/目的の「【元Request/Issue】#xxx」 |
| 8 SubTask分解可能性 | `## SubTask候補` セクション |

---

## よくある記載ミス

| ミスのパターン | 正しい書き方 |
|-------------|------------|
| 完了条件: 「正しく動作すること」 | 「〇〇機能でSSOログインが成功し、ダッシュボードにリダイレクトされること」 |
| 完了条件: 「適切に設定すること」 | 「〇〇の設定値が[具体値]に変更されていること」 |
| 元チケットリンクなし | 「【元Request/Issue】#xxx」を必ず記載 |
| 背景/目的がない | なぜやるかが不明だとSubTask分解時に判断できない |
| 完了条件が1件のみ | 主要な作業項目をすべて列挙（網羅性チェックで⚠️） |
| Title: 「SSO対応」 | 主語・動詞・対象が明確な形式に（「本番環境のSSO設定をOktaに変更する」等） |
