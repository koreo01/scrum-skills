# ebanoide と /pbi:invoke-story-ticket-helper の役割分担

## 共通の入力

両スキルとも **Google Meets 議事録**（Gemini メモ形式）を入力とする。

## 役割の違い

| スキル | 抽出する観点 | 出力 | 受け取り手 |
| --- | --- | --- | --- |
| **ebanoide** | スクラム議論の質的問題（V-1〜V-6, S-3 パターン） | SM 介入候補（Slack DM 文案） | SM（メンバーA） |
| **/pbi:invoke-story-ticket-helper** | チケット化可能な議題・成果物 | IssueType 候補 Draft | メンバーGさん（GitHub Issue 起票時に参照） |

両スキルは**互いに干渉しない**。同じ議事録に対して独立した観点で分析する。

## 同時実行のシナリオ

同じ議事録に対して両スキルを実行することで、2 つの異なる視点を得られる。

- **ebanoide** → スクラム議論のプロセス問題を検出 → メンバーA（SM）が議論改善に活用
- **/pbi:invoke-story-ticket-helper** → 議論の成果物をチケット候補として抽出 → メンバーGさんが PBI 起票に活用

両者を統合した単一スキルにはしない。入力は同じ議事録でも、「議論の質に問題があるか」と「何をチケット化するか」は独立した問いであるため。

## 5/19 議事録での同時実行例

| ebanoide が検出 | invoke-story-ticket-helper が検出 |
| --- | --- |
| V-5（保守表現の多用） → 「一旦」が複数回出現 | Task 候補 → 「レビューデータ検証スクリプト作成」 |
| V-3（判断基準なし並立提案） → 「ヒューマン判定」vs「AI 自動化」 | 判断保留 → 「ヒューマン判定」と AI 自動化の優先順位 |

同じ会議の同じ議論から、観点が異なる両スキルに別々のシグナルが含まれていることが確認できる。
ebanoide は「議論の質に問題がある」と検出し、invoke-story-ticket-helper は「判断保留として記録する」と扱う。

両者を組み合わせて使うのが正しい運用。独立した観点として扱う。
