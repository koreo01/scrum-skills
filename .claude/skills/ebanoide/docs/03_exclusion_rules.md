# 除外フィルタ仕様

ebanoideが**絶対に指摘しない**発言の定義。

## カテゴリ E（Exclusion）

### E-1: 個人事情・健康・休暇

以下のキーワード・パターンを含む発言は完全除外：

- 「体調不良」「通院」「お休みさせてください」「申し訳ありませんが欠席」「早退」
- 「私用で」「家庭の事情で」「子供の都合で」「保育園」「学校」
- 「耳鳴り」「頭痛」「発熱」「お大事に」「療養」
- 「遅刻」「遅れて」「すいません遅くなりました」（単体・短文の場合）

**注意**: 遅刻の事実が業務上の問題（前提共有不足）に発展している場合は、別の角度から分析の余地はあるが、**遅刻そのもの**を指摘対象にしない。

### E-2: 純粋な業務連絡

判断・議論を含まない発言は除外：

- 完了報告（「〜完了しました」「〜対応済みです」「マージしました」）
- スケジュール調整（「〜時から開始します」「会議時間変更」）
- 環境構築・PR作成の通知
- リアクション・感謝（「ありがとうございます」「了解です」「承知しました」）
- 単純な依頼（「確認お願いします」「レビューお願いします」）

### E-3: 事実共有・情報提供（背景・前提が明示されている）

- ドキュメントURL共有とその要約
- 仕様の説明（背景・前提が明示されている）
- データ・ログ・調査結果の報告（数値・事実ベース）

### E-4: 適切な質問（根拠が示されている確認質問）

以下のような発言は**良い質問の例**として除外：

- 「〜という前提で〜と考えていますが、合っていますか?」
- 「Aパターンと判断していますが、Bの可能性もあるでしょうか?」
- 自分の判断・根拠・前提を先に明示してから確認している質問

**判定の要点**: 自分の判断を示しているか / ただ「合ってますか?」と聞くだけか

### E-5: 謝罪・お詫び（業務外）

- 体調・遅刻・欠席に対する謝罪単体
- 「申し訳ありません」「ご迷惑をおかけします」のみで業務的な内容を含まない

### E-6: bot発言・自動投稿

- Slackbot のリマインダー
- GitHub Actions の通知
- Google Calendar の自動通知

### E-7: 雑談・冗談・感情表現単体

- 「お疲れ様です」「おはようございます」などの挨拶
- 議論と無関係な雑談
- 短い感想（「すごい」「面白い」「いいね」）

### E-8: 用語の言い間違い・即時訂正

- 言い間違いをした直後に本人が訂正している
- 「すみません、〇〇でした」のような即訂正

### E-9: 確認のレスポンス（承知・了解）

- 「はい」「了解です」「承知しました」のみの発言
- 議論を前進させていない短いレスポンス

## 除外フィルタの実装ロジック

```python
def should_exclude(utterance: str, context: dict) -> tuple[bool, str]:
    """
    Returns:
        (excluded: bool, reason: str)
    """
    # E-1: 個人事情・健康
    if any(kw in utterance for kw in PERSONAL_KEYWORDS):
        return (True, "E-1: personal_matter")
    
    # E-2: 業務連絡（短文かつ判断を含まない）
    if len(utterance) < 30 and any(kw in utterance for kw in BUSINESS_NOTICE_KEYWORDS):
        return (True, "E-2: business_notice")
    
    # E-6: bot発言
    if context.get("speaker") in BOT_USERS:
        return (True, "E-6: bot")
    
    # E-7: 雑談・挨拶
    if utterance.strip() in GREETING_WORDS:
        return (True, "E-7: greeting")
    
    # E-9: 短いレスポンス
    if utterance.strip() in ACKNOWLEDGMENT_WORDS:
        return (True, "E-9: acknowledgment")
    
    return (False, "")
```

## キーワード辞書（参考実装）

```python
PERSONAL_KEYWORDS = [
    "体調不良", "通院", "お休み", "欠席", "早退", "申し訳ありません",
    "私用", "家庭の事情", "保育園", "幼稚園", "学校",
    "耳鳴り", "頭痛", "発熱", "お大事に", "療養",
    "遅刻", "遅くなりました", "遅れて",
]

BUSINESS_NOTICE_KEYWORDS = [
    "完了しました", "対応済み", "マージしました", "デプロイ",
    "確認お願い", "レビューお願い", "アサインしました",
    "開始します", "実施します",
]

GREETING_WORDS = [
    "お疲れ様です", "おはようございます", "ありがとうございます",
    "よろしくお願いします", "失礼します",
]

ACKNOWLEDGMENT_WORDS = [
    "はい", "了解です", "承知しました", "了解", "承知",
    "ok", "ok です", "オッケー", "なるほど",
]

BOT_USERS = ["USLACKBOT", "Slackbot", "GitHub"]
```

## 注意：判定に迷うケース

### ケース1: 遅刻者が議論を引き継ぐ

```
A: すみません遅くなりました。
B: 大丈夫です、◯◯さんの件から進めますね。
A: では、Xについてですが〜（議論を続ける）
```

→ Aの「すみません遅くなりました」はE-1除外。
→ その後の「Xについて」発言は通常通り分析対象。

### ケース2: 言い間違いの即時訂正

```
A: 営業の進捗ですが、リグレッションが3件発生してます。
B: あれ、リグレッションとデグレって違いますよね?
A: あ、すみません、デグレでした。
```

→ Aの最後の発言はE-8除外。
→ Bの指摘自体は分析対象（むしろ良い指摘の事例）。

### ケース3: 健康事情に関連した業務的影響

```
A: 体調不良で本日休みます。
B: 引き継ぎはどうしますか?
A: 引き継ぎ書を共有済みです。
```

→ A・Bともに業務連絡で判断・議論を含まないのでE-1/E-2除外。

### ケース4: 雑談の中の重要発言（例外的に拾う）

雑談中に重要な発言が混ざる場合がある：

```
A: ところで、あの2月のリリース取り下げの経緯って、どこかに残ってます?
B: いや、特に残ってないですね。
```

→ E-7（雑談）に見えるが、**V-1（過去経緯不明）パターンに該当**するため除外しない。
→ パターン判定が先、除外フィルタは「明らかに無関係」なものだけ弾く設計。

## 除外フィルタの優先順位

1. **bot発言（E-6）**: 即除外
2. **個人事情（E-1）**: 即除外
3. **短文の業務連絡（E-2）**: 文字数で判定（30文字未満かつキーワード一致）
4. **挨拶・短いレスポンス（E-7, E-9）**: 完全一致で除外
5. **言い間違い訂正（E-8）**: 文脈解析（前後の発言を見る）

LLM判定の前段階でルールベースで弾けるものを弾き、コストを節約する。
