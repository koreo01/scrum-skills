## Few-shot 1: 指摘対象例（Tier A）

### Input

```
パターンID: V-3
発言者: メンバーA
タイムスタンプ: 00:12:03
該当発言: "具体今回レストランの例とかでもレストランその養殖行きたい人と
和食行きたい人とみたいなこう5パターンあったみたいなことはで、その同じ人の中でも
なんかこうこん中でランダムみたいなその切り替えペルソナ部分に入れ込むみたいな
ことも、ま、できなくはないですけど、あの、基本的にはやりたいことに対して
それだけ分のペルソナみたいなものを、ま、何らかしの形で用意だく必要ある"
文脈サマリ: ペルソナとシナリオの組み合わせを議論中。複数のパターンを並列して
挙げているが、どのパターンを採用するかの判定軸が示されていない
会議: プロダクトバックログ・リファインメント 4/21
判定根拠: 5パターンの選択肢を並列で示しているが、どの軸で選択するかの判定基準が不在。
「やりたいこと」が抽象的なまま選択肢が議論されている
```

## Few-shot 2: 健全例（指摘対象外）

### Input

```
パターンID: V-3
発言者: メンバーI
タイムスタンプ: 16:03:20
該当発言: "大枠の概念としては理解&違和感なしです。これをどう実現するか?で
考えることが多そうだなという印象でして。例えば
1. シナリオ正常系だけ作って使えるようにする(仮称: テストモードリリース)
2. テストモードで顧客の管理者系の方にトライアル利用いただく
3. トライアル利用の中で異常系を登録 and/or 実際に異常系事態を発生
4. トライアルの中での異常系を踏まえて、AIでプロンプトチューニング & 人間でブラッシュアップ
5. 正式リリース
6. 正式リリース後にも、一定の異常系でミスるケースが発生したら、プロンプトアップデート"
文脈サマリ: AIロープレ異常系シナリオ生成について、実装パターンを6つ提示
会議: Slack スレッド
判定根拠: 6つのステップが並列ではなく時系列で順序立てられている。各ステップで何が起きるか具体的に記述されており、判定軸ではなくフローチャート的構造になっている
```
