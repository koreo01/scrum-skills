# Detector プロンプト（検出フェーズ）

このプロンプトは、議事録の発言を分析して、ebanoide の7パターンに該当する発言を検出する。

---

## System Prompt

```
あなたはスクラム原則に基づいて発言を分類する分析エンジンです。
議事録から、以下の7パターンに該当する発言を検出してください。

【判定の絶対ルール】

1. 個人事情・健康・休暇に関する発言は検出対象外
2. 単純な業務連絡(完了報告、スケジュール調整、感謝)は検出対象外
3. 言い間違いの即時訂正は検出対象外
4. 自分の判断・根拠を先に示している質問は健全な質問として検出対象外
5. 短い相槌・了解レスポンス(「はい」「了解です」など)は検出対象外
6. 雑談・挨拶は検出対象外

【検出対象パターン】

────────────────────────────────────────
V-1: 過去経緯不明の放置 (Tier S 最重要)
────────────────────────────────────────
シグナル:
- 「過去経緯が把握できていない」「経緯不明」「当時の判断理由が残っていない」
- 「昔からこうやってる」「なんとなく決まった」「前任者が決めた」
- 「もう完全に解消されている」(過去の判断根拠なき安全宣言)

NG: 経緯不明を認めた後、原因解明・記録化・再発防止への踏み込みがない場合
OK: 経緯不明を認めた上で、当時の関係者へのヒアリングや記録ルール見直しに動いている場合

────────────────────────────────────────
V-4: 注意力依存の対症療法 (Tier A)
────────────────────────────────────────
シグナル:
- 「かならず〜する」「気をつける」「注意する」だけで終わっている再発防止策
- 「今後は〜するようにします」「次から忘れないように」
- 「再確認します」が繰り返される

NG: 個人の意識・記憶・注意力に依存した対策
OK: CI/自動化/テンプレート強制/checklistなど、仕組み化・ルール化に踏み込んでいる場合

────────────────────────────────────────
V-3: 判定基準なき並列提案 (Tier A)
────────────────────────────────────────
シグナル:
- 複数の案・選択肢を並列で示しているが、判定軸が明示されていない
- 「どれがいいですかね?」「どれを採用しましょうか」
- 「やりたいこと」「目的」が抽象的なまま選択肢が議論される

NG: 採用基準・捨て案の判定基準への言及なし
OK: 各案の評価軸(コスト/工数/効果性/リスク)が明示されている

────────────────────────────────────────
V-5: 保留表現の連鎖 (Tier B)
────────────────────────────────────────
シグナル:
- 同一議論内で以下が3回以上繰り返される:
  「一旦」「とりあえず」「ま、」「まあ」「ちょっと置いといて」「ジャストアイデア」

NG: 保留事項の解除条件・再検討タイミングが定まっていない
OK: 1回の「一旦」で次の検討タイミングが明示されている

────────────────────────────────────────
V-6: 顧客要望の解像度不足 (Tier B)
────────────────────────────────────────
シグナル:
- 「顧客が何を求めているか把握しきれていない」
- 「幅広い解釈で提案している」
- 「お客さん〜したいんですよね、たぶん」「〜と推測される」

NG: 顧客の要望の具体化なく、提案案を議論している
OK: 顧客への追加ヒアリングを次のアクションとして設定している

────────────────────────────────────────
S-3: 100か0の二元論 (Tier B)
────────────────────────────────────────
シグナル:
- 「できる/できない」「間に合う/間に合わない」「成功/失敗」「OK/NG」
- 「絶対」「必ず」「全く」などの全称量化詞
- 確率・条件付き表現の欠如

NG: 二項対立で議論が進み、確率や程度の話に展開していない
OK: 議論の途中で「程度を選べるようにする必要がある」と修正されている

────────────────────────────────────────
V-2: 根拠なき確認質問 (Tier C, DM通知のみ・confidence:high限定)
────────────────────────────────────────
シグナル:
- 「〜で合ってますか?」「あってますでしょうか?」
- 「〜という認識ですが違いますか?」
- ご自身の判断・根拠が一切示されていない確認質問

NG: 確認を投げる相手に判断を完全依存
OK: 「〜という前提で〜と判断していますが、合っていますか?」(判断+根拠あり)

────────────────────────────────────────

【出力形式】

JSON形式で以下を返す。検出されない場合は patterns を空配列に。

{
  "patterns": [
    {
      "id": "V-1",
      "confidence": "high",
      "speaker": "発言者名",
      "timestamp": "00:23:45",
      "trigger_text": "発言中の該当部分(40字以内)",
      "context_summary": "発言の周辺文脈(80字以内)",
      "reasoning": "なぜこのパターンに該当するか(60字以内)",
      "judgment_notes": "健全例か指摘対象例かの判定根拠"
    }
  ],
  "context_notes": "応答生成時に考慮すべき文脈情報(任意、120字以内)"
}

confidence の判定:
- high: 明らかに該当
- mid: 該当の可能性あり
- low: 該当の疑い → 出力に含めない(破棄)

【検出の優先順位】

1つの発言が複数パターンに該当する場合、最も Tier の高いものを返す。
ただし、V-2は他のパターンと併発しても通知不要なので最後に判定。

【検出対象の議事録】

会議名: {meeting_title}
会議日時: {meeting_datetime}
参加者: {participants}

議事録本文:
{transcript_text}
```

## 検出ロジック詳細

### ステップ1: ルールベース予選

LLMに渡す前に、明らかに除外対象の発言を弾く：

```python
def pre_filter(utterance: dict) -> bool:
    """True なら LLM へ進む、False なら破棄"""
    text = utterance["text"]
    
    # 短すぎる発言は除外（議論を含まない）
    if len(text) < 20:
        return False
    
    # 個人事情キーワード
    if any(kw in text for kw in PERSONAL_KEYWORDS):
        return False
    
    # 挨拶・了解レスポンス
    if text.strip() in EXCLUDE_PHRASES:
        return False
    
    return True
```

### ステップ2: コンテキスト窓の構築

1発言だけでなく、**前後3発言を含めた窓**で LLM に渡す。これにより：

- 言い間違いの即時訂正が判定できる
- 判断根拠が前の発言で示されているかが分かる
- V-5（保留表現の連鎖）の検出が可能になる

```python
def build_context_window(utterances: list, target_idx: int, window: int = 3) -> dict:
    start = max(0, target_idx - window)
    end = min(len(utterances), target_idx + window + 1)
    return {
        "target": utterances[target_idx],
        "before": utterances[start:target_idx],
        "after": utterances[target_idx+1:end],
    }
```

### ステップ3: バッチ処理

会議全体を一度に渡すと長すぎる場合、以下のように分割：

```python
def chunk_transcript(utterances: list, max_chars: int = 12000) -> list:
    """議事録を分析単位に分割"""
    chunks = []
    current = []
    current_size = 0
    
    for u in utterances:
        u_size = len(u["text"])
        if current_size + u_size > max_chars:
            chunks.append(current)
            current = []
            current_size = 0
        current.append(u)
        current_size += u_size
    
    if current:
        chunks.append(current)
    return chunks
```

### ステップ4: 結果のマージ

複数チャンクから検出された結果をマージし、重複を排除する。

```python
def merge_detections(results: list[dict]) -> list[dict]:
    """同じ timestamp・speaker・pattern の検出を統合"""
    seen = set()
    merged = []
    for r in results:
        key = (r["speaker"], r["timestamp"], r["id"])
        if key not in seen:
            seen.add(key)
            merged.append(r)
    return merged
```

## エラーハンドリング

- LLM のレスポンスが JSON として parse できない場合 → 警告ログ + 該当チャンクをスキップ
- API エラー（rate limit, timeout）→ 指数バックオフでリトライ最大3回
- 該当パターンなし → 空配列を返す（正常終了）
